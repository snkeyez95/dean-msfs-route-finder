Dean (2026-07-09) finds Opus 4.8 replies too wordy/verbose. Standing rule for this project:
keep replies **brief and on-point, but still detailed and explicit** — and written so a
**non-code-savvy** person understands (plain English, explain any technical term in passing).

**Why:** long recaps bury the answer; Dean wants the point fast without losing the substance.

**How to apply:**
- Lead with the direct answer (yes/no + the one key reason), then supporting detail only if it adds value.
- Prefer tight bullets over paragraphs; bold the takeaway.
- Cut preamble, celebration, and repeated recaps of what we just did.
- Still be explicit and detailed where it matters (don't drop needed specifics to be short) — brevity ≠ vague.
- Plain English always; no jargon without a quick explanation. See [[powershell_51_not_7]] tone.
